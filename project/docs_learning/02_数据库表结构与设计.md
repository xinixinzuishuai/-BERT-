# 02_数据库表结构与设计

## 一、数据库概述

本系统使用 **SQLite** 作为数据库，数据库文件名为 `weibo.db`。SQLite 是一个轻量级的嵌入式数据库，不需要单独的数据库服务器，非常适合中小型应用。

### 数据库配置

**代码位置：** `config.py`

```python
class Config:
    SQLALCHEMY_DATABASE_URI = 'sqlite:///weibo.db'
    SQLALCHEMY_TRACK_MODIFICATIONS = False
```

**说明：**
- `SQLALCHEMY_DATABASE_URI`：数据库连接字符串，`sqlite:///` 表示使用本地 SQLite 数据库
- `SQLALCHEMY_TRACK_MODIFICATIONS`：关闭 SQLAlchemy 的修改追踪功能，提高性能

## 二、核心表结构

### 1. comments 表（评论表）

这是系统中最核心的表，存储所有从微博爬取的评论数据。

**代码位置：** `models.py` 第 7-17 行

```python
class Comment(db.Model):
    __tablename__ = 'comments'
    
    id = db.Column(db.Integer, primary_key=True, autoincrement=True)
    topic_keyword = db.Column(db.String(100), nullable=False, index=True)
    content = db.Column(db.Text, nullable=False)
    create_time = db.Column(db.DateTime, default=datetime.now, nullable=False)
    sentiment_label = db.Column(db.String(20), default=None)
    confidence = db.Column(db.Float, default=None)
    manual_label = db.Column(db.String(20), default=None)
```

### 2. 字段详细说明

| 字段名 | 数据类型 | 是否必填 | 默认值 | 索引 | 业务含义 |
|--------|----------|----------|--------|------|----------|
| **id** | Integer | 是 | 自增 | 主键 | 评论的唯一标识符 |
| **topic_keyword** | String(100) | 是 | 无 | 有 | 话题关键词（如"人工智能"、"新能源汽车"） |
| **content** | Text | 是 | 无 | 无 | 评论的具体内容（用户发布的文字） |
| **create_time** | DateTime | 是 | 当前时间 | 无 | 评论的发布时间 |
| **sentiment_label** | String(20) | 否 | None | 无 | BERT模型预测的情感标签（positive/neutral/negative） |
| **confidence** | Float | 否 | None | 无 | 模型预测的置信度（0-1之间的数值） |
| **manual_label** | String(20) | 否 | None | 无 | 手动标注的情感标签（用于模型评估） |

### 3. 字段业务逻辑详解

#### id（主键）
- **类型：** `Integer`，自增
- **作用：** 每条评论的唯一标识符
- **用途：** 用于精确查询和更新某条评论的情感标签
- **示例：** 1, 2, 3, ..., 1000

#### topic_keyword（话题关键词）
- **类型：** `String(100)`，最大长度100字符
- **是否必填：** 是（`nullable=False`）
- **索引：** 有（`index=True`）
- **作用：** 标识这条评论属于哪个话题
- **业务场景：** 用户在热搜榜上看到"人工智能"话题，点击后，系统会查询 `topic_keyword='人工智能'` 的所有评论
- **示例值：** "人工智能"、"新能源汽车"、"香港突发山火"

#### content（评论内容）
- **类型：** `Text`，无长度限制
- **是否必填：** 是（`nullable=False`）
- **作用：** 存储用户发布的评论文字内容
- **业务场景：** 这是情感分析的核心输入，BERT模型会分析这段文字的情感倾向
- **示例值：** "这个技术太牛了！"、"希望能尽快落地"、"感觉有点夸张"

#### create_time（发布时间）
- **类型：** `DateTime`
- **是否必填：** 是（`nullable=False`）
- **默认值：** `datetime.now`（当前时间）
- **作用：** 记录评论的发布时间
- **业务场景：** 用于绘制时序折线图，分析情感随时间的变化趋势
- **示例值：** "2024-03-25 14:30:00"

#### sentiment_label（情感标签）
- **类型：** `String(20)`，最大长度20字符
- **是否必填：** 否（`default=None`）
- **作用：** 存储BERT模型预测的情感标签
- **取值范围：** 
  - `positive`：积极情感
  - `neutral`：中性情感
  - `negative`：消极情感
  - `None`：尚未分析
- **业务场景：** 
  - 爬虫刚获取评论时，该字段为 `None`
  - BERT模型分析后，更新为具体的情感标签
  - 前端根据这个字段绘制情感分布饼图
- **示例值：** "positive"、"neutral"、"negative"

#### confidence（置信度）
- **类型：** `Float`（浮点数）
- **是否必填：** 否（`default=None`）
- **作用：** 存储模型预测的置信度
- **取值范围：** 0-1之间的数值
- **业务场景：** 
  - 置信度越高，表示模型对该预测越确定
  - 可以用于筛选低置信度的评论进行人工复核
  - 前端可以显示置信度，让用户了解模型的判断依据
- **示例值：** 0.95（非常确定）、0.65（比较确定）、0.51（不太确定）

#### manual_label（手动标注）
- **类型：** `String(20)`，最大长度20字符
- **是否必填：** 否（`default=None`）
- **作用：** 存储人工标注的情感标签
- **取值范围：** 与 `sentiment_label` 相同
- **业务场景：** 
  - 用于模型评估：对比模型预测和人工标注，计算准确率
  - 用于模型优化：收集错误案例，改进模型
  - 用于质量控制：对低置信度的评论进行人工复核
- **示例值：** "positive"、"neutral"、"negative"

## 三、数据库操作方法

### 1. 批量插入评论

**代码位置：** `models.py` 第 35-40 行

```python
@staticmethod
def batch_insert(comments_data):
    comments = []
    for data in comments_data:
        comment = Comment(
            topic_keyword=data.get('topic_keyword'),
            content=data.get('content'),
            create_time=data.get('create_time', datetime.now())
        )
        comments.append(comment)
    db.session.bulk_save_objects(comments)
    db.session.commit()
    return len(comments)
```

**说明：**
- 爬虫获取到评论后，调用此方法批量插入数据库
- 使用 `bulk_save_objects` 提高插入效率
- 返回插入的评论数量

### 2. 查询指定话题的评论

**代码位置：** `models.py` 第 42-46 行

```python
@staticmethod
def get_by_topic(topic_keyword, limit=None):
    query = Comment.query.filter_by(topic_keyword=topic_keyword)
    if limit:
        query = query.limit(limit)
    return query.all()
```

**说明：**
- 根据话题关键词查询评论
- 可以通过 `limit` 参数限制返回数量
- 返回 `Comment` 对象列表

### 3. 更新情感标签

**代码位置：** `models.py` 第 48-54 行

```python
@staticmethod
def update_sentiment(comment_id, sentiment_label, confidence):
    comment = Comment.query.get(comment_id)
    if comment:
        comment.sentiment_label = sentiment_label
        comment.confidence = confidence
        db.session.commit()
        return True
    return False
```

**说明：**
- 根据评论ID更新情感标签和置信度
- BERT模型分析后调用此方法保存结果
- 返回是否更新成功

### 4. 查询未分析的评论

**代码位置：** `models.py` 第 56-57 行

```python
@staticmethod
def get_unanalyzed_comments():
    return Comment.query.filter(Comment.sentiment_label.is_(None)).all()
```

**说明：**
- 查询所有 `sentiment_label` 为 `None` 的评论
- 用于批量情感分析任务
- 返回未分析的评论列表

## 六、答辩常见问题

### Q1: 为什么选择SQLite而不是MySQL？
**标准回答：**
SQLite是一个轻量级的嵌入式数据库，非常适合我的毕设场景。首先，它不需要单独的数据库服务器，部署非常简单，只需要一个.db文件。其次，对于微博评论这种读多写少的应用场景，SQLite的性能完全够用。最后，SQLite支持标准的SQL语法，方便我使用SQLAlchemy ORM进行数据库操作，代码可读性和可维护性都很好。

### Q2: 你的数据库表是如何设计的？为什么这样设计？
**标准回答：**
我设计了一个核心表`comments`，包含7个字段。`id`是主键，`topic_keyword`是话题关键词（加了索引，提高查询速度），`content`是评论内容，`create_time`是发布时间，`sentiment_label`和`confidence`是模型预测结果，`manual_label`是人工标注。这个设计满足了我的业务需求：能够存储评论、进行情感分析、支持模型评估。而且通过索引优化，查询性能也很好。

### Q3: 你的数据库如何处理大量数据的？
**标准回答：**
我在多个层面做了优化。第一，使用了批量插入（bulk_save_objects），减少数据库连接次数。第二，在`topic_keyword`字段上建立了索引，加速按话题查询。第三，使用SQLAlchemy ORM，避免直接写SQL，提高代码可读性和安全性。第四，SQLite本身对于中小型数据量（几千到几万条）的性能就很好，完全满足我的需求。

### Q4: 为什么需要manual_label字段？
**标准回答：**
`manual_label`字段用于模型评估和优化。我需要对比模型预测结果和人工标注结果，计算准确率、F1值等指标，来评估模型性能。同时，通过收集错误案例，我可以分析模型在哪些情况下容易出错，从而针对性地优化模型。这个字段对于保证系统的可靠性和持续改进非常重要。
